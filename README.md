## 🧭 강연 핵심 철학 & 강사의 포지션

> **"한전의 업무는 여러분이 전문가입니다. 저는 AI 기술의 진짜 병목을 뚫는 시스템 엔지니어링을 말하겠습니다."**

본 강연은 시시한 프롬프트 기교를 가르치지 않습니다.  
말(프롬프트)로 때우는 일회성 채팅을 완전히 종식시키고, 프로 엔지니어들이 현업에서 실제로 사용하는 **7대 실전 에이전틱 하네스(Harness) 시스템**을 전수합니다.

---

## 🛠️ 실무 에이전트 통제의 7대 핵심 하네스 기법

1. **폴더 구조 정리 (Folder Architecture)**: 말 대신 `rules/`, `references/`, `input/`, `output/` 표준 디렉토리로 일의 자리를 지정 (경로 이탈 80% 차단)
2. **레퍼런스 잘 주기 (Concrete References)**: 주관적 형용사 10줄 대신, 과거 실제로 결재 통과된 양질의 문서 1장을 주입
3. **컨텍스트 고정 (Context Pinning)**: `CLAUDE.md`로 부서 대원칙, 전결선, 금기 어휘를 영구 고정 (대화가 길어져도 컨텍스트 드리프트 원천 방지)
4. **평가 지표 먼저 만들기 (Acceptance Criteria)**: 기안 작성 전 3대 정량 합격 채점표(누락 0건, 수치 오차 0%, 규정 준수 100%) 사전 확립
5. **스스로 루프 돌게 하기 (Autonomous Self-Healing)**: 채점표를 대조하며 100점이 될 때까지 스스로 수정·재시도하는 자가 치유 루프
6. **멀티에이전트 역할 분담 (Multi-Agent Teaming)**: 한 놈에게 다 시키지 않고 [조사관 - 기안자 - 품질감독관] 3인 1조 분업 가동
7. **적대적 검증 (Adversarial Verification / Red Teaming)**: '너는 이제 까다로운 감사관이다' 페르소나를 부여해 결재 전 가혹하게 결점 난타 및 방어

## 📋 슬라이드 구성 (총 44장)

```
[오프닝 & 프롬프트의 종말]
  01. 표지 (히어로): 프롬프트의 환상을 넘어, 현장 도메인 지식과 에이전트 하네스로
  02. 질문: "프롬프트 길게 쓰느라 진 빼보셨습니까?"
  03. 현실: "프롬프트 열심히 배워봤자, 사무실에선 아무도 못 쓰는 이유"
  04. 종말 선언 [그림]: "프롬프트 엔지니어링은 이미 끝난 문제입니다"
  05. 강사의 태도: "한전 업무는 여러분이 전문가입니다. 저는 기술의 진짜 병목을 말하겠습니다"

[PART 1 · 진짜 AI 병목과 도메인 지식]
  06. 취합의 현실: 각 부서와 협력사에서 쏟아지는 수십 건의 취합 데이터
  07. 병목 ① 텍스트의 함정 [그림]: "텍스트는 평등하지만, 조직의 리스크는 불평등합니다"
  08. 병목 ② 3대 한계: 사내 맥락의 부재 · 감사 리스크 무감각 · 책임의 공백
  09. 병목 ③ 환각의 공포: 규정 물어봤더니 100% 날조 ➔ 감사 지적 리스크
  10. 핵심 명제 ①: "AI는 문장 엮는 기계일 뿐, 조직을 지키는 것은 도메인 지식과 검증 체계"
  11. 병목 비주얼 [그림]: "조직의 진짜 병목은 어디에 있는가?" (현장 암묵지의 미자산화)
  12. 1부 결론: "그렇다면 프롬프트 대신 무엇으로 AI를 일하게 해야 하는가?"

[PART 2 · 프롬프트 없는 세상: 7대 실전 에이전틱 하네스]
  13. 2부 전환 (히어로): 프롬프트 없는 세상, 에이전트를 완벽히 통제하는 6대 하네스
  14. 6대 기법 로드맵: 진짜 고수들이 사용하는 에이전트 통제 시스템 6축
  15. 기법 ① 폴더 구조: "프롬프트로 설명하지 마십시오. 폴더 구조로 일의 자리를 잡습니다"
  16. 표준 폴더 아키텍처: rules/, references/, input/, output/ 4대 표준 폴더
  17. 기법 ② 레퍼런스: "주관적 형용사 10줄보다, 과거 통과된 결재 문서 1장이 압도적입니다"
  18. 레퍼런스 비교: 말로 시키기(실패) vs 레퍼런스 던져주기(완벽 복제)
  19. 기법 ③ 컨텍스트 고정: "새 창 열 때마다 설명하지 마십시오. CLAUDE.md로 원칙 영구 고정"
  20. CLAUDE.md 실물: 부서 전용 시스템 지침서 실제 파일 예시
  21. 기법 ④ 평가 지표: "글을 쓰게 하기 전에, '합격 채점표(Metric)'부터 만들게 하십시오"
  22. 3대 합격 채점표: 누락 0건 · 수치 오차 0% · 규정 준수 100%
  23. 기법 ⑤ 자율 루프 [그림]: "사람이 피드백 주지 마십시오. 채점표 보고 스스로 루프를 돕니다"
  24. 루프 매커니즘: 초안 생성 ➔ 자체 채점 ➔ 자가 치유(수정) ➔ 완료 보고 4단계
  25. 기법 ⑥ 멀티에이전트: "한 놈에게 다 시키면 망합니다. 역할을 쪼갠 팀을 짭니다"
  26. 3인 1조 분업: 조사관(Data Scout) + 기안자(Draft Writer) + 품질감독관(Inspector)
  27. 기법 ⑦ 적대적 검증 [그림]: "너는 이제 까다로운 감사관이다. 기안문의 결점을 가혹하게 찾아내라"
  28. 적대적 검증 3단계: 사규 위반 공격 ➔ 수치 불일치 공격 ➔ 결재 전 완벽 방어
  29. 6대 기법 총괄: "프롬프트는 한 줄도 치지 않았습니다. 오직 하네스만 설계했을 뿐입니다"

[PART 3 · 실전 환경과 공기업 적용]
  30. 식당 vs 주방 [그림]: 남이 지은 식당(SaaS) vs 우리 집 주방(로컬 에이전트 하네스)
  31. 브라우저 제어 [그림]: 사내 포털 및 인트라넷 데이터 자동 연동 시연
  32. 3대 자산 [그림]: 말 대신 사내에 남기는 3대 영구 자산 (Context, Skill, MCP)
  33. 스킬의 위력: 프롬프트 20줄 작성 vs 스킬 파일(SKILL.md) 1줄 호출
  34. 퀴즈 ②: 정기 반복 업무를 자동화할 때 우리 부서에 남겨야 할 자산은?
  35. 바이브코딩: "예쁘게 만들어 줘" 대신 완성 화면 사진을 먼저 던진다
  36. 실무 일치 [그림]: 완성 예시 · 3대 합격 조건 · 샘플 검수 (현업 업무 지시와 일치)
  37. 8단계 프로토콜: 에이전트 기반 업무 자산화 8단계 프로토콜
  38. 보안 안전선: 공기업 환경 3단계 가이드라인 (즉시 가능 / 검토 후 도입 / 사외 반출 금지)
  39. 우선 구축 스킬 3선: 현업 복귀 후 즉시 구축할 첫 스킬 (주간보고 / 민원 / 규정대조)
  40. 사내 확산: 개인의 스킬에서 조직의 영구 자산으로
  41. 실천 다짐: 이번 주에 우리 부서에서 가장 먼저 폴더와 레퍼런스를 갖추고 싶은 업무는?
  42. 현업 복귀 과제: 레퍼런스 폴더 구축, CLAUDE.md 작성, 적대적 검증 루프 적용
  43. 핵심 요약: "프롬프트에 매달리지 마십시오. 폴더, 레퍼런스, 적대적 검증 하네스를 구축하십시오"
  44. 마무리 & Q&A (히어로): "인공지능이 도구를 쥐는 시대. 생산성의 병목은 기술이 아닌 '시스템 하네스'입니다."
```

## ⌨️ 슬라이드 조작 단축키

| 키 | 기능 | 설명 |
|---|---|---|
| `←` `→` / `Space` | **이동** | 슬라이드 앞/뒤 전환 (프레젠터 리모컨 완벽 호환) |
| `S` | **발표자 모드** | 별도 팝업 창에 현재 슬라이드, 대본, 경과 타이머, 다음 슬라이드 미리보기 표시 |
| `O` | **전체보기 그리드** | 44장 전체 슬라이드를 한눈에 보고 원하는 곳으로 즉시 이동 |
| `T` | **테마 전환** | 한전 비즈니스 라이트(기본) / 도쿄 나이트 / 블루프린트 / 다크 나이트 순환 |
| `F` | **전체화면** | 프레젠테이션 전체화면 전환 |
| `R` | **타이머 리셋** | 발표 타이머 초기화 |
