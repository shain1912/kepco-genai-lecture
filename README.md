## 🧭 강연 핵심 철학 & 수업의 목적

> **"프롬프트를 넘어, 현장 도메인 지식과 에이전트 하네스로"**

본 강의는 시시한 프롬프트 작성 요령을 가르치는 국어 수업이 아닙니다.  
말만 하는 챗봇의 한계를 넘어, 내 PC 환경에서 도구를 직접 쥐고 일하는 **자율 에이전트**를 구동하고, 우리 부서의 반복 업무를 실제로 대신할 **소프트웨어 도구를 직접 제작하는 바이브코딩(Vibe Coding)** 실무 교육입니다.

---

## 🛠️ 실무 에이전트를 완벽히 통제하는 7대 핵심 하네스 기법

1. **폴더 구조 (Folder Architecture)**: 말 대신 `rules/`, `references/`, `input/`, `output/` 4대 표준 디렉토리로 업무 자리 잡기 (경로 이탈 및 환각 80% 차단)
2. **레퍼런스 주입 (Concrete References)**: 모호한 설명 대신 과거 실제로 결재 통과된 양질의 문서 원본 1장 주입 (100% 서식 복제)
3. **CLAUDE.md (Context Pinning)**: 매번 반복 설명하지 않고 부서 대원칙, 전결선, 금기 사항을 단 하나의 시스템 파일로 영구 고정 (Context Drift 원천 방지)
4. **정량 Metric (Acceptance Criteria)**: 기안 작성 전 3대 합격 채점표(누락 0건, 수치 오차 0%, 사규 조항 100%) 사전 확립
5. **자가 치유 루프 (Autonomous Loop)**: 사람이 매번 지적하지 않고 에이전트가 채점표를 보며 100점이 될 때까지 스스로 수정·재시도 (Self-Healing)
6. **멀티에이전트 팀 (Multi-Agent Teaming)**: 한 프롬프트에 몰아넣지 않고 조사관 · 기안자 · 검수관으로 역할을 분리한 3인 1조 전문 분업
7. **적대적 검증 (Adversarial Verification / Red Teaming)**: 결재 상신 전 감사관 관점에서 사규 위반과 수치 오류를 가혹하게 지적하고 방어

## 📋 슬라이드 구성 (총 40장)

```
[오프닝 & 핵심 개념: 챗봇을 넘어 에이전트로]
  01. 표지 (히어로): 프롬프트를 넘어, 현장 도메인 지식과 에이전트 하네스로
  02. 문제 제기: 프롬프트 템플릿 복사하기. 언제까지 반복해야 할까요?
  03. 핵심 개념 [그림]: 챗봇은 조언자, 에이전트는 실행자입니다.
  04. 환경의 차이 [그림]: 정해진 메뉴판의 식당 vs 내 도구를 쓰는 주방
  05. 패러다임 종말 [그림]: 프롬프트 기교의 시대는 이미 끝났습니다.
  06. 수업의 목적: 바이브코딩. 글짓기가 아닌, 실제 도구의 제작.
  07. 강의 아젠다: 오늘 함께 다룰 3가지 핵심 과제 (1부 / 2부 / 3부)

[PART 1 · AI의 사내 한계와 실무 도메인 지식]
  08. 실무의 현실: 매일 마주하는 부서와 사업소 데이터 취합
  09. 구조적 한계 ① [그림]: 텍스트는 평등하지만, 조직의 리스크는 다릅니다.
  10. 구조적 한계 ②: AI가 혼자서는 결재 문서를 완성할 수 없는 3가지 이유 (맥락 · 감사 · 책임)
  11. 컴플라이언스: 지어낸 사규 조항. 감사 지적으로 이어지는 환각의 위험.
  12. 핵심 통찰: AI는 문장 도구일 뿐, 조직을 지키는 것은 도메인 지식입니다.
  13. 병목의 본질 [그림]: 진짜 병목은 사람 머릿속에 갇힌 업무 기준입니다.
  14. 1부 결론: 프롬프트 대신, 무엇으로 에이전트를 움직여야 할까요?

[PART 2 · 에이전트를 완벽히 통제하는 7대 실전 하네스]
  15. 2부 전환 (히어로): 7대 실전 하네스. 에이전트를 통제하는 시스템 설계.
  16. 기법 ① 폴더 구조 [그림]: 폴더 구조. 명확한 자리가 만드는 질서.
  17. 표준 폴더 아키텍처: 실무 자동화를 위한 4대 표준 폴더 (rules, references, input, output)
  18. 기법 ② 레퍼런스: 모호한 형용사 대신, 통과된 결재 문서 원본을 제시합니다.
  19. 지시 방식 비교: 말로 설명하기 vs 합격 문서 던져주기
  20. 기법 ③ CLAUDE.md: CLAUDE.md. 부서의 원칙을 파일로 고정합니다.
  21. CLAUDE.md 실물: 부서 전용 지침서 (CLAUDE.md 예시 파일)
  22. 기법 ④ Metric [그림]: Metric의 중요성. 작성 전에 합격선부터 세웁니다.
  23. 3대 합격 지표: 보고서 자동 통과를 위한 3대 평가 기준 (완전성, 정합성, 사규 준수)
  24. 기법 ⑤ 자율 루프 [그림]: 자가 치유 루프. 채점표를 보고 스스로 수정합니다.
  25. 루프 매커니즘: 스스로 완주하는 자율 루프 4단계 (초안 ➔ 채점 ➔ 자가수정 ➔ 완료)
  26. 기법 ⑥ 멀티에이전트 [그림]: 멀티에이전트 팀. 역할을 분리한 전문 협업.
  27. 3인 1조 팀 구성: 보고서 완성을 위한 3인 1조 분업 (조사관 · 기안자 · 검수관)
  28. 기법 ⑦ 적대적 검증 [그림]: 적대적 검증. 결재 전 감사관 관점으로 결점을 찾습니다.
  29. 사전 필터링 3단계: 결재 상신 전 감사관 에이전트의 3단계 검증
  30. 7대 하네스 총괄: 프롬프트 작성이 아닌, 시스템(Harness) 설계를 통한 업무 완성

[PART 3 · 바이브코딩 실전과 공기업 현업 적용]
  31. 업무 자산화 [그림]: 일회성 대화 대신 남기는 3대 영구 업무 자산 (Context · Skill · MCP)
  32. 실전 효율 비교: 매주 프롬프트 복붙하기 vs 스킬 파일 한 줄 호출
  33. 실습 시연 [그림]: 브라우저 제어를 통한 사내 전산망 데이터 자동 연결
  34. 작업 지시 기준: "예쁘게 만들어 줘" 대신 완성 화면 예시와 합격 기준을 던집니다.
  35. 일하는 방식 [그림]: 후배 직원에게 일을 지시하고 검수하던 방식 그대로
  36. 표준 절차: 에이전트 기반 업무 자산화 8단계
  37. 보안 가이드라인: 공기업 환경을 위한 3단계 보안 기준 (즉시 / 검토 / 반출 엄금)
  38. 우선 구축 과제 3선: 현업 복귀 후 바로 만들 수 있는 첫 과제 3선 (주간보고 · 민원 · 규정대조)
  39. 실천 과제: 이번 주에 추진할 3가지 현업 과제
  40. 마무리 & Q&A (히어로): 인공지능이 도구를 쥐는 시대. 경쟁력의 본질은 '시스템 하네스'입니다.
```

## ⌨️ 슬라이드 조작 단축키

| 키 | 기능 | 설명 |
|---|---|---|
| `←` `→` / `Space` | **이동** | 슬라이드 앞/뒤 전환 (프레젠터 리모컨 완벽 호환) |
| `S` | **발표자 모드** | 별도 팝업 창에 현재 슬라이드, 대본, 경과 타이머, 다음 슬라이드 미리보기 표시 |
