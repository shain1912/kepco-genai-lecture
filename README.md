# 한국전력공사 특강 — 프롬프트를 넘어 현장 도메인 지식과 에이전트 업무자산화로

한국전력공사 재직자 특강용 통합 HTML 프레젠테이션 슬라이드 (총 39장)

## 🧭 강연 핵심 철학

> **"프롬프트는 중요하지 않습니다. 이미 멀티턴과 스킬로 해결된 하위 기술입니다. 진짜 중요한 것은 현장의 '도메인 지식'이며, 조직의 유일한 병목은 '현장의 암묵지를 꺼내어 자산화하는 것'입니다."**

본 과정은 프롬프트 작성 요령 같은 미봉책을 다루지 않습니다.  
한국전력공사 현장 실무자가 가진 독보적인 도메인 지식을 어떻게 언어화하고, **스킬 파일(SKILL.md)**과 **에이전트 루프**를 통해 부서의 영구 자산으로 축적할 것인지를 다룹니다.

## 📋 슬라이드 구성 (총 39장)

```
[오프닝 & 문제 제기]
  01. 표지: 프롬프트의 환상을 넘어, 현장 도메인 지식과 에이전트 구축으로
  02. 사전 점검: 프롬프트 잘 쓰려고 애써보셨습니까? 왜 실무에선 겉돌까요?
  03. 강의 개요: 프롬프트 만능론을 넘어 본질적 병목을 해결하는 여정
  04. 오늘의 실무 산출물: 프롬프트 템플릿이 아닙니다. '현장 도메인 지식 정의서'입니다
  05. 실무자의 진짜 역할: 프롬프트 타이핑이 아닌, 현장 지식을 정의하고 검증하는 지휘자

[PART 1 · 프롬프트의 한계와 현장 도메인 지식]
  06. 프롬프트의 환상: 프롬프트 강의 백날 들어봐야 실무에 안 쓰이는 이유
  07. 기술의 현주소: 프롬프트 엔지니어링은 이미 끝난 문제입니다 (멀티턴 & 스킬의 해결)
  08. 라이브 사례: 현장 순시 메모 — 무엇이 진짜 좋은 보고서를 만드는가?
  09. 도메인 지식의 주입: 차이를 만든 본체는 프롬프트가 아니라 '현장 도메인 지식'
  10. 핵심 메시지 ①: "프롬프트는 단순한 그릇일 뿐, 본체는 당신의 도메인 지식입니다"
  11. 진짜 병목(Bottleneck): 모델의 성능이 아닙니다. '현장의 암묵지가 갇혀 있는 것'이 병목입니다
  12. 라이브 시연 ②: 사내 규정 질의 — 프롬프트로 환각을 막을 수 있는가?
  13. 환각의 본질: 환각은 프롬프트로 못 막습니다. '검증 하네스'로 통제합니다
  14. 환각 검증 원칙: "이 내용이 맞아?"가 아니라 "사내 규정 원본의 어느 조항인가?"
  15. 사내 보안 통제: 보안 역시 프롬프트 지시가 아닌 '로컬 시스템 마스킹'으로 통제
  16. Part 1 결론: 프롬프트 작성에 시간 쓰지 마십시오. 도메인 지식 정제에 집중하십시오

[PART 2 · 프롬프트의 종말: 에이전트 기반 업무 자산화]
  17. 2부 전환: 프롬프트의 종말, 현장 지식을 '스킬'로 자산화하는 에이전트
  18. 프롬프트 한계: 매번 프롬프트를 새로 치는 것은 가장 비효율적인 방식입니다
  19. 챗봇 vs 에이전트: 자판기(단발 프롬프트)와 직원(멀티턴 자율 루프)의 차이
  20. 3대 자산: 사내에 남겨야 할 3대 영구 자산 (Context, Skill, MCP + CLI)
  21. 라이브 시연 ④: 프롬프트 20줄 작성 vs 도메인 지식 스킬(SKILL.md) 호출 비교
  22. 퀴즈 ②: 정기 반복 업무를 자동화할 때 우리 부서에 남겨야 할 자산은?
  23. 식당 vs 주방: 남이 지은 식당(외부 SaaS) vs 우리 집 주방(사내 로컬 에이전트)
  24. 3대 질문: 사내 자동화 도입 시 반드시 던져야 할 3대 질문 (데이터, 도구, 지속성)
  25. 3단계 로드맵: 공기업 업무자동화의 3단계 발전 로드맵 (챗봇 -> CLI -> 스킬 자산화)
  26. 실무 과제 발굴: 우리 부서 업무 중 도메인 지식은 뻔한데 손이 많이 가는 반복 작업은?
  27. 라이브 시연 ⑤: 웹 브라우저 자동화 — 사내 포털 및 인트라넷 데이터 연동
  28. 라이브 시연 ⑥: 오류 발생 시 에이전트의 자가 치유(Self-healing) 프로세스
  29. 퀴즈 ④: 에이전트가 오류를 만났을 때 보인 행동은? (로그 보고 스스로 재실행)
  30. 라이브 시연 ⑦: 바이브코딩 — 모호한 프롬프트 대신 시각적 목표와 합격 기준을 부여
  31. 실무 프로세스: 완성 예시 · 3대 합격 조건 · 샘플 검수 (현업 지시와 일치)
  32. 하네스 8단계: 에이전트 기반 업무 자산화 8단계 표준 프로토콜

[PART 3 · 공기업 현실과 실행]
  33. 보안 안전 가이드: 공기업 환경을 고려한 3단계 보안 가이드라인
  34. 우선 구축 스킬 3선: 현업 복귀 후 즉시 적용 가능한 우선 구축 스킬 (주간보고/민원/규정)
  35. 사내 확산 단계: 개인 업무 효율에서 조직의 업무 자산으로 확장하는 여정
  36. 실천 과제 확정: 이번 주에 우리 부서에서 가장 먼저 스킬로 만들고 싶은 업무는?
  37. 현업 과제: 현업 복귀 후 추진할 3단계 실천 과제 (스킬 작성, 회의 공유, 지침 확인)
  38. 핵심 요약: "프롬프트는 기술이 아닙니다. 진짜 병목은 현장의 암묵지를 꺼내는 것입니다"
  39. 마무리 & Q&A: "인공지능이 도구를 쥐는 시대. 생산성의 병목은 기술이 아닌 '현장 지식'입니다."
```

## ⌨️ 슬라이드 조작 단축키

| 키 | 기능 | 설명 |
|---|---|---|
| `←` `→` / `Space` | **이동** | 슬라이드 앞/뒤 전환 (프레젠터 리모컨 완벽 호환) |
| `S` | **발표자 모드** | 별도 팝업 창에 현재 슬라이드, 대본, 경과 타이머, 다음 슬라이드 미리보기 표시 |
| `O` | **전체보기 그리드** | 39장 전체 슬라이드를 한눈에 보고 원하는 곳으로 즉시 이동 |
| `T` | **테마 전환** | 한전 라이트(기본) / 도쿄 나이트 / 블루프린트 / 다크 나이트 등 순환 |
| `F` | **전체화면** | 프레젠테이션 전체화면 전환 |
| `R` | **타이머 리셋** | 발표 타이머 초기화 |

## ⚠️ 교육용 자료 고지

슬라이드에 등장하는 **순시 메모, 사내 지침(○○사업소 설비이상 보고 지침), 고객 민원 데이터는 전부 교육용 가상 자료**입니다. 실재하는 한국전력공사의 규정·설비·고객 정보와 무관하며, 실무 판단의 근거로 사용할 수 없습니다.
