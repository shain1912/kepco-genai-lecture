## Part 1 · 생성형 AI 실무 활용

AI를 잘 쓰는 법이 아니라, **어디까지 맡기고 어디부터 사람이 볼 것인가**를 정하는 두 시간입니다.
수강생은 강의가 끝날 때 "우리 팀 AI 사용 판단 기준" 한 장을 채워서 들고 나갑니다.

| # | 라이브 시연 | 남기는 문장 |
|---|---|---|
| ① | 같은 일, 프롬프트 3종 | 차이를 만든 건 AI 성능이 아니라 **내가 준 판단 기준**이다 |
| ② | AI가 규정을 지어낼 때 | "맞아?"가 아니라 **"어디를 보면 확인돼?"** 라고 묻는다 |
| ③ | 넣어도 되는 정보 / 안 되는 정보 | 자동으로 지우고, **사람이 한 번 더 본다** |

`handout.md` 는 수강생 배포용 자료입니다 — 판단 기준 양식과 프롬프트 템플릿이 들어 있습니다.

시연 ①·②는 **녹화 영상**으로 진행합니다. 응답 지연 때문이 아니라, 프롬프트 A의 출력이 매번 달라지고
환각 시연은 모델이 "모른다"고 답해 버리면 무너지기 때문입니다. 시연 ③(개인정보 마스킹)만 현장에서 직접 실행합니다.

> 온라인 공개본에서는 영상이 유튜브로 연결됩니다. **확대·하이라이트 연출은 강의장 버전에서만** 재생됩니다.

## ⚠️ 자료에 대한 고지

슬라이드에 나오는 **순시 메모, 사내 지침, 고객 민원 데이터는 전부 교육용으로 지어낸 가상 자료**입니다.

- 실재하는 한국전력공사의 규정·설비·고객 정보와 **무관**합니다.
- 특히 "○○사업소 설비이상 보고 지침(제3조·제4조·제5조)"은 **실재하지 않는 문서**이며,
  AI가 규정을 지어내는 현상을 시연하기 위해 만든 것입니다. **실무 판단의 근거로 사용할 수 없습니다.**
- 이름·연락처·주소·고객번호는 모두 임의로 만든 값입니다.

이 자료는 특정 AI 서비스나 모델을 추천하지 않습니다.
슬라이드에 모델명을 넣지 않은 것은 자료 수명과 조직별 상황 차이를 고려한 의도적 선택입니다.

## 슬라이드 조작

브라우저로 열면 바로 동작합니다. 외부 CDN·빌드·인터넷 연결이 필요 없습니다.

| 키 | 동작 |
|---|---|
| `←` `→` (또는 `Space`, `PageUp/Down`) | 이동 — 프레젠터 리모컨 그대로 동작 |
| `S` | 발표자 모드 (노트 · 경과 타이머 · 계획 시각 · 다음 슬라이드) |
| `Shift+S` | 발표자 화면을 별도 창으로 (듀얼 모니터) |
| `F` | 전체화면 |
| `R` | 타이머 초기화 |
| `B` 또는 `.` | 검은 화면 |
| `?` | 조작키 도움말 |

클릭·터치 스와이프로도 넘어갑니다.

### 강당 환경을 전제로 넣은 안전장치

500명 규모 대강당에서 사고가 나는 지점을 코드에서 막아 두었습니다.

- 애니메이션이 어떤 이유로든 멈춰도 **내용은 반드시 표시됩니다** (백지 방지)
- 프로젝터 연결로 해상도가 바뀌면 슬라이드를 넘길 때마다 **자동 재계산**
- 내용이 세로 공간을 넘으면 **넘친 만큼만 자동 축소**
- 시스템 설정이 "동작 줄이기"면 애니메이션 없이 즉시 표시

## Part 2 · 프롬프트의 종말 — 에이전트 시대의 업무자동화

말(프롬프트) 대신 컨텍스트·스킬·MCP 등 **영구 자산**을 남기는 업무 패러다임 전환을 다룹니다.
Claude 코딩 에이전트 및 바이브코딩을 활용한 120분 특강 슬라이드(28장)입니다.

| 섹션 | 주제 | 핵심 내용 |
|---|---|---|
| **01** | **프롬프트의 종말** | 챗봇 vs 에이전트 · 지속성 3층 (Context, Skill, MCP) + CLI |
| **02** | **식당에서 주방으로** | AI 기능 소비자에서 작업 흐름 설계자로 전환 · 3단계 진화 |
| **03** | **라이브 시연** | Chrome 제어 · Computer Use · 사내 웹 디자인 · 자가 치유(Self-healing) |
| **04** | **현실과 실행** | 망분리 환경의 현실적 대안 · 부서별 첫 스킬 후보 3종 선정 |
