## 🧭 강연 핵심 철학

> **"프롬프트는 중요하지 않습니다. 이미 멀티턴과 스킬로 해결된 하위 기술입니다. 진짜 중요한 것은 현장의 '도메인 지식'이며, 조직의 유일한 병목은 '현장의 암묵지를 꺼내어 자산화하는 것'입니다."**

본 과정은 자잘한 프롬프트 기교를 가르치지 않습니다.
빽빽한 글 대신 **1 Slide 1 Message 원칙**, **대형 폰트(Big Font)**, **12종의 고해상도 맞춤 일러스트**를 전면 배치하여 1초 만에 메시지가 뇌리에 각인되도록 설계되었습니다.

## 📋 슬라이드 구성 (총 47장)

```
[오프닝 & 프롬프트 종말]
  01. 표지 (히어로): 프롬프트의 환상을 넘어, 현장 도메인 지식과 에이전트로
  02. 질문: "프롬프트 잘 쓰려고 애써보셨습니까?"
  03. 사전 설문: 최근 실무에서 AI를 써봤을 때 가장 큰 문제는?
  04. 현장의 현실: "프롬프트 열심히 배웠는데... 결국 뻔한 교과서 답변만 나옵니다"
  05. 프롬프트 종말 [그림]: "프롬프트 엔지니어링은 이미 끝난 문제입니다"
  06. 이유 1: 멀티턴(Multi-turn) 대화로 이미 해결된 영역
  07. 이유 2: 스킬(Skill) 파일 하나로 이미 해결된 영역
  08. 강의 로드맵: 두 가지 본질적 질문 (도메인 지식 & 에이전트 자산화)
  09. 오늘의 실무 산출물: 프롬프트가 아닌 '현장 도메인 지식 정의서' 1장
  10. 실무자의 역할: 프롬프트 타이핑이 아닌 '현장 지식을 정의하고 검증하는 지휘자'

[PART 1 · 현장 도메인 지식과 조직의 병목]
  11. 라이브 사례: 오늘 오전의 거친 순시 메모 4줄
  12. 본체의 발견 [그림]: 차이를 만든 본체는 한전 실무자의 '도메인 지식'
  13. 지식의 언어화: 3대 판단 기준 (변압기 이상음 [즉시] / 피복 점검 [계획] / 환풍기 [기록])
  14. 핵심 명제 ①: "프롬프트는 단순 그릇, 결과물의 가치는 당신의 도메인 지식입니다"
  15. 현업의 질문: "AI가 계속 발전하면, 내 일은 줄어들까요?"
  16. 역할의 분리: 실행의 층(AI가 흡수) vs 판단의 층(사람의 고유 책임)
  17. 진짜 병목 [그림]: "AI 시대, 조직의 진짜 병목(Bottleneck)은 어디에 있는가?"
  18. 병목의 해부: 모델 성능 부족이 아니라 현장의 암묵지가 갇혀 있는 것이 병목
  19. 라이브 검증: 야간 순시 중 사내 규정을 AI에 물어보았다
  20. 검증 결과: 조항 번호, 보고 시한, 특례 전부 지어낸 완벽한 가짜 규정
  21. 기술의 본질: 환각은 버그가 아니라 언어모델의 확률적 동작 원리
  22. 실무 원칙 [그림]: "이거 맞아?"가 아니라 "원본 규정의 몇 조 몇 항인가?" (원문 대조)
  23. 사내 보안: "개인정보 빼줘" 프롬프트는 유출 — 로컬 비식별화 도구로 통제
  24. 1부 결론: 프롬프트 작성에 시간 쓰지 마십시오. 도메인 지식 정제에 집중하십시오

[PART 2 · 프롬프트의 종말: 에이전트 기반 업무 자산화]
  25. 2부 전환 (히어로): 현장 지식을 '스킬'로 자산화하는 에이전트
  26. 반복의 비효율: 매주 월요일마다 프롬프트를 복사하는 가장 미련한 방식
  27. 본질적 차이: 챗봇은 '자판기', 에이전트는 '현장 대리인'
  28. 3대 자산 [그림]: 말 대신 사내에 남기는 3대 영구 자산 (Context, Skill, MCP)
  29. 실전 비교: 프롬프트 20줄 작성 vs 스킬 파일(SKILL.md) 단 1줄 호출
  30. 퀴즈 ②: 정기 반복 업무를 자동화할 때 우리 부서에 남겨야 할 자산은?
  31. 환경 비교 [그림]: 남이 지은 식당(외부 SaaS) vs 우리 집 주방(사내 로컬 에이전트)
  32. 도입 검토 기준: 사내 자동화 도입 시 던져야 할 3대 질문 (데이터, 도구, 지속성)
  33. 발전 로드맵: 공기업 업무자동화의 3단계 로드맵 (웹 챗봇 -> 로컬 CLI -> 부서 스킬)
  34. 실전 워크숍: 우리 부서 업무 중 도메인 지식은 뻔한데 손이 많이 가는 반복 작업은?
  35. 라이브 시연 ① [그림]: 웹 브라우저 자동 제어 (사내 포털 데이터 연동)
  36. 라이브 시연 ② [그림]: 실패시켰을 때 스스로 고치는 자가 치유(Self-healing)
  37. 퀴즈 ④: 에이전트가 실행 실패를 만났을 때 한 일은? (로그 보고 스스로 재실행)
  38. 바이브코딩: "예쁘게 만들어 줘" 대신 완성 화면 사진을 먼저 던진다
  39. 실무 일치 [그림]: 완성 예시 · 3대 합격 조건 · 샘플 검수 (현업 업무 지시와 일치)
  40. 표준 프로토콜: 에이전트 기반 업무 자산화 8단계 프로토콜

[PART 3 · 공기업 실행과 확산]
  41. 보안 안전선: 공기업 환경 3단계 가이드라인 (즉시 가능 / 검토 후 도입 / 사외 반출 금지)
  42. 우선 구축 스킬 3선: 현업 복귀 후 즉시 구축할 첫 스킬 (주간보고 / 민원 / 규정대조)
  43. 사내 확산: 개인의 스킬에서 조직의 영구 자산으로
  44. 실천 다짐: 이번 주에 우리 부서에서 가장 먼저 만들고 싶은 스킬은?
  45. 현업 복귀 과제: 현업 복귀 후 추진할 3단계 실천 과제 (스킬 작성, 팀 회의 10분, 보안 확인)
  46. 핵심 요약: "프롬프트는 기술이 아닙니다. 진짜 병목은 현장의 암묵지를 꺼내는 것입니다"
  47. 마무리 & Q&A (히어로): "인공지능이 도구를 쥐는 시대. 생산성의 병목은 기술이 아닌 '현장 지식'입니다."
```

## ⌨️ 슬라이드 조작 단축키

| 키 | 기능 | 설명 |
|---|---|---|
| `←` `→` / `Space` | **이동** | 슬라이드 앞/뒤 전환 (프레젠터 리모컨 완벽 호환) |
| `S` | **발표자 모드** | 별도 팝업 창에 현재 슬라이드, 대본, 경과 타이머, 다음 슬라이드 미리보기 표시 |
| `O` | **전체보기 그리드** | 47장 전체 슬라이드를 한눈에 보고 원하는 곳으로 즉시 이동 |
| `T` | **테마 전환** | 한전 비즈니스 라이트(기본) / 도쿄 나이트 / 블루프린트 / 다크 나이트 순환 |
| `F` | **전체화면** | 프레젠테이션 전체화면 전환 |
| `R` | **타이머 리셋** | 발표 타이머 초기화 |
