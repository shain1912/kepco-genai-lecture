현업 실무자로서 가져야 할 3가지 핵심 판단 역량을 강조합니다.

도입 초기 현업의 주된 피드백

"업무에 써보려고 시도했는데,
일반론적이고 교과서적인 답변만 나옵니다."
원인 1 · 현업 판단 기준의 미제공

단순히 "요약해 달라"고만 요청할 뿐, 우리 부서가 우선적으로 고려해야 할 판단 잣대를 주지 않았습니다.

원인 2 · 사내 맥락(Context)의 부재

한전의 업무 지침, 특정 설비 이력, 보고 양식이 모델에 사전 전달되지 않은 상태에서 질의했습니다.

현업에서 AI를 도입했을 때 실망하는 대표적인 이유 두 가지를 짚습니다.

문제를 분리하여 접근한다

프롬프트로 해결 가능한 영역 vs 실무자가 판단할 영역

프롬프트 및 스킬로 해결 가능한 영역
서식 불일치 · 표현의 모호함 · 일반론적 문장
→ 독자 정의, 보고 양식 고정, 우선순위 분류 기준 제공으로 100% 개선 가능합니다.
실무자가 직접 판단해야 하는 영역
현장 사실관계 확인 · 규정 부합성 · 결재 책임
→ 실무 도메인 지식, 사실 검증, 최종 집행 책임은 온전히 사람의 몫입니다.
도구로 해결할 부분과 실무자가 직접 통제할 영역을 명확히 구분합니다.
🔴 라이브 시연 ① · 실무 사례

오전 현장 순시 점검 메모 원자료

3호 변압기 쪽 소리 좀 이상함. 웅- 하는 소리가 평소보다 큼. 2호 피더 케이블 피복 약간 긁힘 흔적 있음. 당장 문제는 없어 보임. 동관 2층 분전반 정기점검 완료. 이상 무. 변전실 환풍기 먼지 많이 쌓여서 소음 심함. 청소 필요.

현장에서 작성된 거친 메모를 상급자 보고서로 가공할 때, 모델에게 어떤 지침을 주어야 할까요?

실제 현장에서 작성되는 거친 메모 데이터를 제시하고 프롬프트 3종을 비교합니다.

프롬프트 3종 비교 분석

프롬프트 C — 판단 기준을 명확한 문장으로 전달

【보고 독자】 결재권자 (현장 미동행, 당일 긴급 조치 우선순위 결정) 【분류 기준】 · [즉시]: 당일 고장 및 안전사고로 직결될 수 있는 항목 (예: 변압기 이상음) · [계획]: 주간 단위 일정 수립 후 조치할 항목 (예: 케이블 피복 점검) · [기록]: 별도 조치 불필요, 단순 현황 관리 【안전장치】 · 확인되지 않은 수치나 사내 규정을 임의로 지어내지 말 것. · 추가 확인이 필요한 항목은 [정보부족]으로 명시할 것.
품질을 결정하는 4대 설계 요소
독자 특정누가 보고서를 읽고 어떤 결정을 내리는가
분류 기준현장의 경중(즉시/계획/기록)을 언어화하여 제공
오류 방어근거 없는 추정 대신 [정보부족] 표기 강제
양식 제약결재권자가 한눈에 파악할 수 있는 3문단 구성
품질의 차이는 모델의 차이가 아니라 판단 기준을 명문화했는지 여부에서 발생합니다.

시연 ①의 결론

결과물의 차이를 만드는 것은 모델 성능이 아닌,
'실무자가 정의한 판단 기준'입니다

변압기 소음이 케이블 청소보다 시급하다는 판단은 인공지능이 내린 것이 아닙니다.
한국전력공사 실무자가 현장에서 오랜 경험을 통해 축적한 도메인 지식입니다.

현장 도메인 지식이 결과물의 가치를 결정함을 강조합니다.

기술 발전과 실무자의 역할

AI 모델이 고도화될수록, 도메인 지식의 중요성은 커집니다

실행의 영역 (AI 자동화 가속)

초안 작성, 표준 서식 변환, 요약, 코드 생성, 데이터 정리 등.

시간이 지날수록 AI의 처리 범위가 넓어지고 실행 속도는 비약적으로 향상됩니다.

판단의 영역 (전문가의 고유 책임)

무엇이 중요한가? 규정의 본래 취지는 무엇인가? 현장 위험 수준은 얼마인가?

기술이 발전해도 판단의 책임은 경감되지 않으며, 결과에 대한 최종 책임은 실무자가 집니다.

실행은 자동화하되 판단의 통제권은 실무자가 확고히 유지해야 합니다.

  • 모바일 스마트폰으로 외부 생성형 AI 서비스에 접속함.

기술 구조의 이해

환각은 단순 오류가 아닌 언어모델의 동작 원리

검색 엔진 (Search Engine)
색인된 문서를 찾아 제공한다

언어모델의 기본 작동 원리가 다음 토큰 확률 예측임을 설명합니다.

결재권자의 우선순위와 실무 경중을 문장화하여 프롬프트에 제공합니다.

3

사전 비식별화 통제

PART 2 · 에이전트 기반 업무자동화

단순 질의응답을 넘어,
업무 시스템과 자산을 남기는 단계로

프롬프트 반복 입력을 탈피하는 에이전트 워크플로우와 실전 구축 방안

2부에서는 단순 대화창을 넘어 부서의 업무 자산으로 구축하는 방법을 다룹니다.

업무 방식의 전환

일회성 프롬프트 작업이 가진 구조적 한계

반복 프롬프트 입력의 비효율
  • 매주 정기 업무 때마다 긴 프롬프트를 다시 복사하고 수정해야 합니다.
  • 채팅창을 새로 열 때마다 부서 규정과 서식을 처음부터 설명해야 합니다.
  • 개인이 만든 좋은 프롬프트가 팀의 표준 프로세스로 축적되지 않습니다.
에이전트 스킬 파일 기반의 자산화
  • 말(프롬프트) 대신 표준 파일(SKILL.md)로 매뉴얼화합니다.
  • 한 번 정의해 두면 후임자에게 그대로 인수인계가 가능합니다.
  • 사내 문서, 엑셀, 브라우저를 에이전트가 직접 제어하여 완수합니다.
프롬프트의 휘발성을 지적하고 영구 자산화의 필요성을 설명합니다.

개념 정의

챗봇과 에이전트의 구조적 차이

비교 항목챗봇 (Chatbot)에이전트 (Agent)
동작 방식 1회성 질의응답 (1 Query - 1 Response) 목표 부여 시 스스로 계획-실행-검증 루프 수행
도구 연동 채팅창 내 텍스트 출력에 국한 로컬 파일 편집, 브라우저 조작, 터미널 명령어 실행
예외 처리 오류 발생 시 답변 중단 또는 오답 출력 에러 로그를 스스로 분석하고 자가 치유(Self-healing)
챗봇은 자판기이고 에이전트는 일을 끝까지 수행하는 현장 대리인입니다.

프롬프트 대신 남기는 것들

사내 업무에 남기는 3대 자산과 실행 인터페이스

컨텍스트부서 인수인계 문서 — CLAUDE.md. 우리 부서의 공통 규칙과 원칙 정의.
스킬업무 표준 매뉴얼 — SKILL.md. 정기 반복 업무의 절차와 합격 조건 명시.
MCP표준 접속 규격 — 전력 규격처럼 사내 데이터베이스와 도구를 안전하게 연결.
CLI지휘 인터페이스 — 웹 버튼 클릭 대신 자연어 명령으로 전체 워크플로우 통제.

방식 B · 표준 SKILL.md 파일 호출

업무자동화 도입 시 검토 사항

사내 시스템 구축 시 확인해야 할 3대 질문

1. 데이터 보존 위치

사외 서버 전송 없이, 사내 인프라 및 로컬 PC 내에서 안전하게 가공되는가?

2. 실무 도구 제어권

채팅창에 머무르지 않고, 사내 파일·엑셀·브라우저를 직접 제어할 수 있는가?

3. 조직 자산화 여부

개인 활용에 그치지 않고, 팀원 및 후임자에게 인수인계 가능한 파일로 보존되는가?

공기업에서 자동화 시스템을 검토할 때 필수적인 3가지 기준입니다.

업무 자동화 발전 경로

공기업 업무자동화의 3단계 발전 로드맵

1단계 · 질의응답

웹 챗봇 활용

웹 포털에 텍스트 복사·붙여넣기. 개인 비서 수준 활용, 자동화 연속성 부재.

2단계 · 도구 연동

로컬 CLI 도입

로컬 환경에서 대용량 파일 및 시스템 연동. 처리 속도와 생산성의 비약적 확장.

3단계 · 자산 구축

부서 스킬 표준화

부서별 업무 매뉴얼(SKILL.md)과 MCP 연계. 담당자가 부재해도 표준 절차 완수.

대부분 1단계에 머물러 있는 현실을 짚고 2~3단계로 나아가는 경로를 제시합니다.
📊 실무 과제 발굴

사내 업무 중 반복적인 수작업 소요가 가장 큰 영역은?

핵심 업무 명칭을 작성해 주십시오

예: 월간 실적 취합 · 민원 회신문 초안 작성 · 점검표 사진 대조 · 규정 신구대조표

청중의 실제 업무 과제를 현장에서 즉각 취합하여 다음 시연과 연결합니다.
🔴 라이브 시연 ⑤ · 브라우저 자동화

웹 브라우저 자동 제어: 포털 및 인트라넷 데이터 연동

수작업시스템 로그인 → 검색 조건 입력 → 엑셀 다운로드 → 수작업 복사 (20분)
에이전트브라우저 자동 제어 → 데이터 탐색 및 스크랩 → 표준 양식 보고서 생성 (15초)

💡 별도의 API가 없는 사내 웹 시스템이라도 사람이 브라우저로 수행하던 클릭과 조회를 그대로 자동화합니다.

에이전트가 브라우저를 직접 조작해 실무 데이터를 가져오는 과정을 보여줍니다.
🔴 라이브 시연 ⑥ · 자가 치유

예외 상황 발생 시 에이전트의 자가 치유(Self-healing)

Self-healing 루프의 동작 과정

1. 명령어 실행 또는 파일 파싱 중 예외 에러 발생
2. 에이전트가 중단되지 않고 터미널 에러 로그를 분석
3. 원인 파악 후 수정 코드를 자동 작성하여 재실행
4. 검증 기준 충족 시 최종 완료 보고

"사람이 오류를 보고 수동으로 고치는 것이 아니라, 오류를 분석하고 스스로 수정하는 루프를 부여합니다."

실패했을 때 스스로 해결하는 에이전트의 루프 능력을 시연합니다.

●

■

정답은 ● 에러 로그를 분석하고 스스로 수정하여 재실행했다입니다.

모호한 텍스트 대신, 시각적 목표와 합격 기준을 명시

비효율적인 프롬프트 지시

"우리 부서 사내 대시보드 화면 하나 보기 좋게 깔끔하게 만들어 줘."

→ 주관적 형용사는 모델마다 다르게 해석되어 재작업이 반복됩니다.

검증 가능한 바이브코딩 방식

1. 완성 형태의 예시(Mockup) 이미지를 먼저 제공합니다.
2. 필수 데이터 및 합격 조건 3가지를 수치로 제시합니다.
3. 에이전트가 코드를 작성하고 브라우저에서 직접 검증합니다.

모호한 텍스트 대신 시각적 레퍼런스와 합격 기준을 주는 방식을 설명합니다.

친숙한 업무 방식

완성 예시 · 3대 합격 조건 · 샘플 검수

완성 예시목표 제시 — "이 규격과 레이아웃에 맞추어 산출물 작성"
합격 조건체크리스트 — 필수 수치 포함, 규정 서식 준수, 누락 0건
샘플 검수최종 확인 — 실무자가 첫 결과물을 확인하고 피드백 반영
이 방식은 현업에서 후배 직원에게 업무를 지시하고 검수하는 프로세스와 완전히 같습니다.

부서별 우선 추진 과제

현업 복귀 후 즉시 적용 가능한 우선 구축 스킬 3선

A
주간업무 실적 취합

팀원별 메모 5건을 부서 표준 양식 1장으로 가공. 합격 조건: 3문단 구성, 수치 근거 명시, 표준 경어체 통일.

기획 · 관리 부서
B
민원 답변 초안 작성

민원 유형별 필수 안내 항목과 공문 표준 톤을 스킬 매뉴얼로 표준화. 실무자는 최종 사실관계 검수만 수행.

고객 · 영업 부서
C
규정 신구 조문 대조표

개정 전·후 규정을 나란히 대조하고 변경 조항을 자동 비교 표기. 검증 조건: 조항 누락 0건.

총무 · 감사 부서
부서별로 즉시 구축해 볼 수 있는 대표적인 실전 스킬 3가지를 소개합니다.

전사 자산 연계
