PART 2 · 프롬프트의 종말

그런데 언제까지,
매번 프롬프트로 주문만 할 것인가?

말 대신 '남기는 것'으로 넘어가는 에이전트 업무자동화의 세계

이제 프롬프트 입력창을 벗어나 진짜 업무 시스템을 구축하는 2부로 들어갑니다.

프롬프트 = 주문 내용

프롬프트는 창을 닫으면 사라진다

매번 반복되는 프롬프트 피로
  • 매주 월요일마다 긴 프롬프트를 다시 복사·붙여넣기 한다.
  • 새 채팅창을 열 때마다 우리 부서 규정을 처음부터 다시 가르친다.
  • 내가 만든 좋은 프롬프트를 옆 자리 동료에게 온전히 전달하기 어렵다.
에이전트가 가져온 패러다임 전환
  • 말(프롬프트) 대신 파일(코드·설정)로 남긴다.
  • 한 번 만들어 두면 인수인계 문서처럼 계속 작동한다.
  • 사내 파일, 웹 브라우저, 데이터베이스를 직접 실행한다.
프롬프트의 휘발성을 지적하고, 영구 자산화의 필요성을 제기합니다.

개념 정의

챗봇과 에이전트는 완전히 다르다

구분챗봇 (Chatbot)에이전트 (Agent)
동작 방식 한 번 묻고 한 번 답한다 (1 Request - 1 Response) 목표를 주면 스스로 루프를 돌며 문제를 해결한다
도구 사용 텍스트만 출력 (직접 파일을 고치지 못함) 파일 읽기/쓰기, 브라우저 제어, 터미널 명령 실행
실패 시 행동 틀린 채로 답변을 끝내거나 멈춘다 에러 로그를 확인하고 스스로 다시 시도(Self-healing)
챗봇은 상담원이고, 에이전트는 일을 맡아 끝까지 해오는 현장 대리인입니다.

"우리 팀 주간보고 양식은 3문단이고, 첫 문단은 실적이고, 두 번째는 계획이고, 음슴체 쓰지 말고..."

→ 매주 10분씩 프롬프트를 다듬어야 함. 전달 불가.

방법 B · SKILL.md 파일 장착

단 한 줄 호출: "이번 주 주간보고 취합해 줘"

→ 에이전트가 폴더 내 SKILL.md를 자동으로 읽고 부서 규격 100% 일치 결과물 생성.

스킬 파일 하나가 프롬프트 수십 줄을 영구적으로 대체하는 현장을 시연합니다.

정답은 ◆ 업무 매뉴얼 파일(스킬)입니다. 프롬프트를 길게 쓰는 건 하책입니다.

비유로 이해하기

남이 지은 식당, 우리 집 주방

SaaS 식당정해진 메뉴판만 주문 가능. 내 재료(사내 데이터)를 가져가서 요리해 달라고 할 수 없음.
에이전트 주방내 칼, 내 양념, 내 냉장고. 우리 부서의 레시피대로 마음껏 자동화 도구를 조립한다.
외부 포털 챗봇에 의존하는 것과, 사내 PC에 로컬 에이전트 주방을 세팅하는 것의 차이입니다.

선택의 기준

세 가지 질문만 던져 보세요

1. 데이터는 어디에?

남의 서버(클라우드)로 보내지 않고, 내 컴퓨터 로컬 환경에서만 안전하게 처리되는가?

2. 도구가 연결되는가?

텍스트 대화창에 머물지 않고, 내 컴퓨터의 파일·엑셀·브라우저를 직접 열고 닫을 수 있는가?

3. 자산으로 남는가?

대화가 끝나면 휘발되지 않고, 다음 사람에게 인수인계할 수 있는 파일로 영구 보존되는가?

공기업에서 AI를 도입할 때 검토해야 할 3대 질문입니다.

업무 혁신의 로드맵

그래서 "손(설치)"이 필요하다

1단계 · 웹 챗봇

말 걸기 (초보)

포털에 들어가서 복사·붙여넣기. 매번 새로 설명해야 함. 편하지만 확장이 막힘.

2단계 · CLI 도구

손 얹기 (중급)

터미널/에이전트 설치. 로컬 파일과 시스템에 직접 접근 시작. 생산성 10배 폭발.

3단계 · 하네스 & 스킬

부서 자산화 (고수)

우리 부서 전용 매뉴얼(스킬)과 MCP 연동. 사람이 없어도 규격대로 자동 완수.

대부분 1단계에 머물러 있습니다. 오늘 2단계와 3단계로 넘어가는 문을 엽니다.

여기서 나온 답변 하나를 바로 다음 라이브 시연의 즉석 소재로 연결합니다.
🔴 라이브 시연 ⑤ · 브라우저 제어

브라우저는 "남의 집". 에이전트가 거기까지 간다

기존 방식사내 포털 접속 → 로그인 → 검색 → 다운로드 → 엑셀 열기 (사람 손 20분)
에이전트헤드리스 브라우저 실행 → 데이터 탐색 및 스크랩 → 취합 파일 생성 (10초)

💡 API가 없는 폐쇄형 웹사이트라도 사람이 브라우저로 하던 모든 동작을 그대로 대행합니다.

실제 브라우저 창이 스스로 열려 검색하고 데이터를 가져오는 과정을 보여줍니다.
🔴 라이브 시연 ⑥ · 자가 치유

일부러 실패시킨다 — 그리고 스스로 다시 한다

Self-healing (자가 치유 루프)

1. 명령 실행 중 예기치 않은 오류 발생
2. 에이전트가 멈추지 않고 터미널 에러 로그를 분석
3. 원인 파악 후 수정 코드를 작성하여 스스로 재실행
4. 최종 성공 후 완료 보고

"사람이 오류를 보고 고치는 게 아니라, 오류를 보는 눈을 에이전트에게 줍니다."

일부러 문법 오류나 파일 경로 오류를 냈을 때 에이전트가 어떻게 대처하는지 확인합니다.

▲
멈추고 기다렸다
◆

●

정답은 ● 로그를 보고 스스로 다시 했다입니다. 루프의 존재가 에이전트의 핵심입니다.
🔴 라이브 시연 ⑦ · 바이브코딩

"만들어 달라"가 아니라, 완성 사진을 먼저

실패하는 프롬프트

"우리 부서 사내 대시보드 웹페이지 하나 예쁘게 만들어 줘."

→ 모호한 형용사('예쁘게')는 AI마다 제각각 해석하여 쓸 수 없는 결과물이 나옴.

성공하는 바이브코딩

1. 완성 사진(Mockup 이미지)을 먼저 던진다.
2. 합격 조건 3줄을 명시한다.
3. 에이전트가 코드를 짜고 브라우저에서 직접 검수한다.

말 대신 시각적 목표를 주는 바이브코딩의 정석을 시연합니다.

낯설지 않은 이유

완성 사진 · 합격 조건 3줄 · 샘플 검수

완성 사진목표 시각화 — "이렇게 나와야 합니다" 레퍼런스 제시
합격 조건3줄 체크리스트 — 수치 일치, 필수 양식, 누락 0건
샘플 검수눈으로 확인 — 첫 결과물을 보고 피드백 1회 제공
이건 개발자만 하는 게 아닙니다. 현장에서 후배 직원에게 일 시킬 때 늘 하시던 방식 그대로입니다.

에이전트와 일하는 8단계

주방을 세팅하고, 루프를 돌리고, 매뉴얼로 남긴다

1-2단계
목표 정의

완성 화면 정의 & 3줄 합격 조건 명시

3-4단계
컨텍스트 주입

CLAUDE.md 및 사내 규칙 주입

5-6단계
루프 실행

에이전트 자율 실행 & 에러 자가 치유

스킬 자산화

SKILL.md로 저장해 부서 전체 공유

8단계 하네스 사이클을 거치면 단순 일회성 작업이 팀의 영구 자산으로 바뀝니다.

총무 · 감사

사내 확산 로드맵

지속성의 3단계 여정

STEP 1
개인 스킬

내 PC에서 내 업무를 줄이는 용도. 5분짜리 SKILL.md 하나 작성.

STEP 2
팀 매뉴얼

팀 공유 폴더에 커밋. "우리 팀 양식은 이 스킬 돌려"로 인수인계 완료.

STEP 3
전사 자산

사업소 간 검증된 스킬 공유. 사내 에이전트 허브로 전사 생산성 증대.

혼자 쓰다 끝나는 게 아니라 팀과 조직의 자산으로 승격시키는 방법입니다.
