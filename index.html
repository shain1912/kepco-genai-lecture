핵심 개념

챗봇은 조언자,
에이전트는 실행자입니다.

챗봇: 대화창에 갇혀 조언만 합니다. 파일 수정도, 전산망 조회도 결국 사람이 직접 해야 합니다.

에이전트: 도구를 직접 쥡니다. 내 컴퓨터의 파일, 폴더, 브라우저를 스스로 다루며 일을 끝냅니다.

말만 하는 챗봇과 직접 일하는 에이전트의 차이를 명확히 구분합니다.

환경의 본질

정해진 메뉴판의 식당 vs
내 도구를 쓰는 주방

외부 클라우드 챗봇은 남의 식당입니다. 정해진 메뉴판 밖의 우리 사내 데이터를 다룰 수 없습니다.

에이전트는 우리 집 주방입니다. 내 PC의 고유 문서와 규정집을 꺼내 자유롭게 조리합니다.

외부 SaaS와 사내 로컬 환경의 차이를 주방 메타포로 설명합니다.

이제 중요한 것은 일하는 구조(Harness)를 짜는 일입니다.

프롬프트 엔지니어링의 종말과 시스템 설계의 도래를 선언합니다.

실무 현장

매일 마주하는 부서와 사업소의 데이터 취합

실무자가 매주 취합하는 원자료

· 사업소별 주간 실적 메모 및 엑셀 수치 취합
· 협력업체 정기 점검 결과서 및 공정률 보고
· 반복되는 대민 민원 내역 및 현장 특이사항
· 상위 부처 요청 긴급 통계 자료

AI에게 그냥 요약시켰을 때

"이거 취합해서 보고서 양식으로 요약해 줘."

결과: 일반론적인 뻔한 보고서 출력.
→ 이번 분기 본부 중점 관리 지표도, 결재권자의 보고 방향도 전혀 반영하지 못함.

실제 공기업 관리자들이 겪는 취합 보고의 문제를 짚습니다.

구조적 한계 ①

텍스트는 평등하지만,
조직의 리스크는 다릅니다.

AI에게 취합 문서의 100줄은 모두 똑같은 '글자(토큰)'일 뿐입니다.

어떤 숫자가 감사 지적 대상이고, 어떤 문장이 상부 보고의 핵심인지는 오직 실무자만이 압니다.

AI의 언어 처리와 실무자의 리스크 판단 사이의 간극을 설명합니다.

구조적 한계 ②

AI가 혼자서는 결재 문서를 완성할 수 없는 3가지 이유

한계 1

사내 맥락의 부재

이번 분기 본부 중점 지표와 결재 라인의 보고 성향은 세상 어떤 AI 학습 데이터에도 없습니다.

한계 2

감사 리스크 무감각

표현 하나, 산술 오차 하나가 감사원이나 내부 감사에서 어떤 지적으로 이어지는지 AI는 모릅니다.

한계 3

책임의 공백

AI는 엉터리 기안을 올려도 책임지지 않습니다. 최종 결재에 도장을 찍고 책임지는 것은 실무자입니다.

맥락, 감사, 책임이라는 3대 근본 한계를 짚습니다.

컴플라이언스

지어낸 사규 조항. 감사 지적으로 이어지는 환각의 위험.

"사내 계약 규정에 따른 수의계약 한도와 예외 조항을 정리해 줘.
※ 절대 틀리지 말고, 확실한 사규 조항만 사실대로 답변하세요."

결과: 존재하지도 않는 제14조 제3항을 지어내어 결재 상신 시 심각한 감사 지적 초래.

규정과 감사에서 환각이 초래하는 실제 업무 리스크를 설명합니다.

첫 번째 통찰

AI는 문장 도구일 뿐,
조직을 지키는 것은 도메인 지식입니다.

프롬프트를 화려하게 쓰는 것보다,
실무자의 판단 기준과 검증 체계가 시스템에 녹아있어야 합니다.

도메인 지식과 검증 체계의 결합을 강조합니다.

병목의 본질

진짜 병목은
사람 머릿속에 갇힌 업무 기준입니다.

AI 모델 성능의 문제가 아닙니다.

우리 부서가 일하는 방식과 판단 기준이 문서나 규칙으로 자산화되지 못한 것이 유일한 병목입니다.

암묵지를 형식지로 전환하는 시스템 자산화의 필요성을 짚습니다.

실전 기법 ① · 아키텍처

폴더 구조.
명확한 자리가 만드는 질서.

프롬프트에 매번 긴 규칙을 적지 않습니다.

디렉토리 구조를 깔끔하게 잡아주는 것만으로 에이전트의 경로 이탈과 환각을 80% 줄입니다.

말 대신 폴더 구조로 맥락을 잡는 원리를 설명합니다.

표준 폴더 규격

실무 자동화를 위한 4대 표준 폴더

📂 rules/

부서 업무 지침, 결재 전결 규정, 필수 준수 보안 가이드라인 문서

📂 references/

과거 실제로 통과된 최고 등급 결재 보고서 및 엑셀 원본 샘플

📂 input/

이번 주에 처리해야 할 정제되지 않은 현장 메모 및 사업소 취합 원자료

📂 output/

에이전트가 검증을 거쳐 최종 출력할 표준 규격 결재 기안서

실제 사내 적용을 위한 4대 디렉토리 구조를 제시합니다.

실전 기법 ② · 레퍼런스

모호한 형용사 대신,
통과된 결재 문서 원본을 제시합니다.

"깔끔하고 격조 있게 써줘"라는 지시는 실패합니다.
"이 폴더에 있는 작년 결재 문서 서식과 문체 그대로 작성해 줘"가 가장 확실합니다.

양질의 통과 문서를 직접 던져주는 것의 효과를 설명합니다.

지시 방식의 차이

말로 설명하기 vs 합격 문서 던져주기

말로 설명하는 프롬프트 방식
"3문단으로 쓰고, 첫 줄은 개요 쓰고..."
줄바꿈, 글머리 기호(■, ▶, -), 문체 규칙이 매번 어긋나 결국 수작업 수정 발생.
레퍼런스 문서 제공 방식
"references/2025_주간실적.md 참고해"
기존 통과 문서의 문체, 보고 분량, 서식 규칙을 정확히 파악하여 그대로 복제.
레퍼런스 기반 산출물의 높은 일치도를 보여줍니다.

실전 기법 ③ · 컨텍스트 유지

CLAUDE.md
부서의 원칙을 파일로 고정합니다.

새 대화창을 열 때마다 부서 규정을 다시 설명할 필요가 없습니다.
부서의 전결선, 보고 어조, 금기 사항을 단 하나의 시스템 파일로 고정합니다.

CLAUDE.md를 통한 컨텍스트 고정 기법을 설명합니다.

파일 실물 예시

부서 전용 지침서 (CLAUDE.md 예시)

# [기획관리부 실무 에이전트 지침] 1. 문서 어조: 공기업 표준 개조식 종결어미(~함, ~임) 엄격 준수. 구어체 금지. 2. 수치 검증: 예산 및 실적 수치는 input/ 자료와 1원의 오차도 없어야 함. 3. 사규 대조: 규정 조항 인용 시 반드시 rules/ 최신 규정집 번호와 대조할 것. 4. 보안 원칙: 고객 식별정보 발견 시 작업을 즉시 중단하고 마스킹 처리할 것.

이 파일 하나만 폴더 루트에 두면, 팀원 누가 에이전트를 켜도 동일한 부서 기준으로 작동합니다.

실제 업무 지침 파일의 구조를 보여줍니다.

실전 기법 ④ · 평가 지표

Metric의 중요성.

정량적 평가 기준의 사전 확립 필요성을 설명합니다.

정량적 통과 기준

보고서 자동 통과를 위한 3대 평가 기준

완전성 지표

누락 항목 0건

사업소별 필수 보고 항목(실적, 계획, 특이사항)이 단 하나도 빠짐없이 포함되었는가?

정합성 지표

수치 오차 0%

본문 요약 수치의 합계가 취합 엑셀의 원본 SUM 수치와 100% 완벽히 일치하는가?

적합성 지표

사규 준수 100%

인용한 사규 조항이 rules/ 폴더의 최신 개정판 조항 번호와 100% 부합하는가?

완전성, 정합성, 적합성의 3대 지표를 제시합니다.

실전 기법 ⑤ · 자가 치유

자가 치유 루프.
채점표를 보고 스스로 수정합니다.

사람이 매번 틀린 곳을 찾아 피드백 주지 않습니다.

에이전트가 채점표를 확인하며 100점이 될 때까지 스스로 고치고 다시 작성합니다.

에이전트 자율 루프의 메커니즘을 설명합니다.

자율 루프 메커니즘

스스로 완주하는 자율 루프 4단계

STEP 1

초안 작성

input 자료와 레퍼런스를 참조해 1차 기안문 작성

STEP 2

자체 채점

사전에 정의된 3대 Metric으로 1차 초안 검증

STEP 3

자가 수정

"수치 오차 1건 발견" ➔ 재계산 후 해당 문장 자체 수정

STEP 4

완료 보고

모든 지표 100점 통과 확인 후 사람에게 최종 제출

루프 4단계를 도식화하여 보여줍니다.

업무 자산화

일회성 대화 대신 남기는
3대 영구 업무 자산

컨텍스트 (CLAUDE.md): 부서 대원칙과 보고 지침
스킬 (SKILL.md): 도메인 지식이 담긴 실행 매뉴얼
MCP: 사내 시스템과 데이터를 안전하게 연결하는 표준 도구

실전 효율

매주 프롬프트 복붙하기 vs 스킬 파일 한 줄 호출

구시대 프롬프트 방식
매주 메모장에서 프롬프트 20줄 복사·붙여넣기
"우리 부서 양식은 3문단이고, 실적 먼저 쓰고, 경어체 쓰고..." 매주 수작업 반복.
에이전트 스킬 방식
단 1줄 호출: "주간보고 취합해 줘"
에이전트가 폴더 내 SKILL.md(도메인 매뉴얼)를 읽고 부서 규격 100% 일치 결과물 자동 생성.
스킬 파일 자산화의 실질적 시간 절감 효과를 보여줍니다.

실습 시연

브라우저 제어를 통한
사내 전산망 데이터 자동 연결

브라우저 자동 조작 시연을 연결합니다.

작업 지시의 기준

"예쁘게 만들어 줘" 대신,
완성 화면 예시와 합격 기준을 던집니다.

모호한 말로 설명하지 않고,
완성 화면 목업(Mockup) 사진과 3대 합격 지표를 주고 코드를 생성·수정하는 것이 바이브코딩의 정석입니다.

바이브코딩의 실제 작업 지시 원리를 설명합니다.

후배 직원에게 일을 지시하고

모범 샘플 보여주기 ➔ 기준 정하기 ➔ 초안 받아 검수하기.

새로운 기술이 아닙니다. 우리가 원래 현업에서 일하던 방식과 완벽히 일치합니다.
